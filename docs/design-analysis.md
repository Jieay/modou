# 墨斗 IDE 界面问题分析与设计方案

## 一、当前问题诊断

### 1.1 为什么界面"黑乎乎不像 IDE"

**根本原因：Iced 框架的渲染能力限制**

| 问题 | 原因 | 影响 |
|------|------|------|
| 纯色背景无层次 | Iced 的 `container::Style` 只支持纯色背景 | 缺乏 VS Code 的微妙阴影和渐变 |
| 无圆角和阴影 | Iced 不支持 CSS 式的 `box-shadow` 和复杂 `border-radius` | 界面显得生硬、简陋 |
| 字体渲染粗糙 | Iced 默认字体渲染未针对代码优化 | 等宽字体显示效果差 |
| 无图标系统 | 使用 Emoji 代替专业图标 | 显得业余、不统一 |
| 分隔线生硬 | 只能用 1px 纯色边框 | 缺乏 VS Code 的微妙分隔效果 |

### 1.2 为什么鼠标点击没有作用

**技术原因分析**

1. **Iced 的 `button` 样式问题**：自定义 `Style` 时可能覆盖了默认的交互反馈
2. **事件冒泡被拦截**：嵌套的 `container` 可能阻止了事件传递
3. **坐标计算错误**：`scrollable` 内部的点击坐标转换可能有问题
4. **状态更新未触发重绘**：`update` 返回 `Task::none()` 但视图未正确刷新

打造一个 **视觉上接近 VS Code**、**交互上符合 macOS 原生习惯** 的轻量 IDE。

### 2.2 参考原型

打开 `docs/design-prototype.html` 查看高保真设计原型：

```bash
open docs/design-prototype.html
```

## 三、技术实现路径

### 3.1 方案 A：优化现有 Iced 实现（推荐）

**优势**：保持纯 Rust 技术栈，无需重写

**具体措施**：

1. **修复鼠标点击**
   - 检查 `button` 的 `on_press` 是否正确绑定
   - 确保 `Style` 不会阻止事件传递
   - 添加 `mouse_area` 作为备选方案

2. **提升视觉效果**
   - 使用 `canvas` 自定义绘制阴影和渐变
   - 实现自定义 `Widget` 替代标准组件
   - 优化字体渲染设置

3. **改进图标系统**
   - 使用 `svg` 图标代替 Emoji
   - 统一图标尺寸和风格

### 3.2 方案 B：切换到 egui（备选）

**优势**：`egui` 的即时模式 GUI 更适合复杂自定义渲染

**劣势**：需要重写 UI 层

### 3.3 方案 C：使用 Tauri + Web 前端（激进）

**优势**：可以直接使用 HTML/CSS 实现任意视觉效果

**劣势**：违背"纯 Rust 原生"的设计初衷

## 五、总结

当前界面问题的根源是 **Iced 框架的默认渲染效果较为基础**，需要通过自定义绘制和组件来实现 VS Code 级别的视觉效果。

建议采用 **方案 A（优化现有 Iced 实现）**，先修复鼠标点击问题，再逐步提升视觉效果。
