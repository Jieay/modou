# 墨斗（Modou）开发计划：三方终端停靠（Terminal Docking）

> 本文档是给 AI 编程助手使用的执行规格。目标读者不是"想了解方向的读者"，而是"要直接动手改代码的执行者"。
> 因此文档以可直接执行为第一原则：给出精确的文件路径、接口签名、数据结构、状态机、验收标准与陷阱清单。
> 除本文明确授权的改动外，不得改动其他文件或行为。

## 0. 一句话目标

把主窗口右侧区域改造成「第三方终端停靠槽」：启动用户选定的真实终端应用（首选 iTerm2），把该应用的独立窗口精确吸附到主窗口右侧，并随主窗口移动、缩放、折叠、关闭而联动。**不开发任何终端仿真代码。**

- 第一期（P1）：右侧停靠槽 + iTerm2 provider 最小闭环。
- 第二期（P2）：provider 抽象配置化，接入 Terminal.app / WezTerm / Alacritty / kitty / 自定义命令，并提供设置界面。
- 第三期（P3）：全屏、多桌面、多显示器、脱锚重吸、会话恢复等边界情况。

## 1. 背景与硬约束（AI 助手必须先读）

### 1.1 现有代码事实

- 技术栈：Tauri 2 + 原生 HTML/CSS/JS（`src/`，无构建工具、无框架、无 npm）+ Rust 后端（`src-tauri/`）。
- 左栏编辑器已使用 Monaco（VS Code 同内核），本期**不修改**编辑器能力。
- 现有底部 `#panel` 里的 xterm.js + 自研 PTY（`src-tauri/src/terminal.rs`、`src/app.js` 中的 `initXterm`/`createTerminal`）是 **legacy 代码**：
  - P1/P2 **不得删除**，只保持其不可达（用一个 `state.legacyTerminalEnabled = false` 开关禁用），防止回滚成本。
  - P3 再决定是彻底删除还是保留为「未安装终端/未授权」时的隐藏后备。
- 前端 `app.js` 使用 `var`、全局函数、无模块化的旧式风格。新增代码沿用此风格，不引入 ES module、打包器或框架。
- Rust 侧不使用新的异步运行时（tokio 等）；后台任务用 `std::thread` + `std::sync::mpsc`。
- `tauri.conf.json` 当前 `csp: null`、`withGlobalTauri: true`。本期不恶化即可，不在本计划范围内修复。
- 仓库当前没有任何 commit，工作区即现状。禁止执行 `git reset --hard`、`git checkout --` 等破坏性命令。

### 1.2 平台硬约束

- macOS **不允许**把另一个 App 的窗口嵌入自己窗口（没有跨进程窗口宿主 API）。
  - 因此「套个框」= **窗口级停靠**：两个独立窗口，程序化贴合。这是唯一能用真 iTerm2 的方式，已与用户确认接受。
- 移动/缩放其他 App 的窗口需要**辅助功能（Accessibility）权限**；用 AppleScript 控制 iTerm2/Terminal.app 需要**自动化（Automation）授权**。两类授权都要在 UI 里做显式引导。
- 本期只支持 macOS。所有新增后端能力用 `#[cfg(target_os = "macos")]` 门控；非 macOS 编译必须通过，相关命令返回 `Err("not supported on this platform")`。
- **不新增** Tauri shell 插件。进程一律用 `std::process::Command`（含 `osascript`）。

### 1.3 命名与序列化约定

- Tauri command：Rust 侧 `snake_case` 函数名，前端 `invoke('snake_case', { camelCase 参数 })`（Tauri 自动把 JS camelCase 映射为 Rust snake_case 字段）。
- Tauri event：Rust 侧 `emit` 的 payload 结构体统一加 `#[serde(rename_all = "camelCase")]`，前端读 camelCase。
- 事件名统一用 `dock://` 前缀。
- 新增 Rust 结构体凡要越过 IPC 的，必须 `#[derive(Clone, Serialize, Deserialize)]` 且**不得**包含非序列化句柄（如 AXUIElement、文件描述符）；句柄只存在 Rust 内存中，前端只见其 id/标题。

### 3.2 设置结构（`settings.rs`）

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default)]
pub struct TerminalSettings {
    pub default_provider: String,        // "iterm2"
    pub width_ratio: f64,                // 0.38，槽宽 = 编辑区宽度 * ratio
    pub follow_window: bool,             // true
    pub auto_redock: bool,               // true，脱锚后是否自动吸回
    pub redock_interval_ms: u64,         // 250
    pub quit_behavior: QuitBehavior,     // Close
    pub providers: Vec<ProviderConfig>,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "camelCase")]
pub enum QuitBehavior { Close, Quit, Leave }

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default)]
pub struct ProviderConfig {
    pub id: String,               // "iterm2" | "wezterm" | ...
    pub name: String,             // 展示名
    pub kind: ProviderKind,       // Applescript | Cli
    pub enabled: bool,
    pub app_name: Option<String>, // AX 查找用进程/应用名

}
```

## 4. 坐标系与几何换算（必须精确，易错）

全部换算成 **macOS 全局逻辑点（global points，主屏左上角为原点，可含负数）** 再操作 AX。

```rust
// 纯函数，必须配单元测试
pub struct Rect { pub x: f64, pub y: f64, pub w: f64, pub h: f64 }

/// css: 前端 getBoundingClientRect() 得到的槽矩形（CSS px，相对 webview 内容区左上角）
/// inner: Tauri window.inner_position()（物理像素）
/// scale: window.scale_factor()
pub fn css_to_global(css: Rect, inner: PhysicalPosition<i32>, scale: f64) -> Rect {
    let logical = inner.to_logical::<f64>(scale);
    Rect {
        x: logical.x + css.x,
        y: logical.y + css.y,
        w: css.w,
        h: css.h,
    }
}
```

依据：

- 浏览器 CSS px == macOS 逻辑点（`devicePixelRatio` == `scale_factor()`）。
- `inner_position()` 是客户区左上角的物理像素坐标；当前 `titleBarStyle: "Overlay"`，内容区与窗口基本重合，槽矩形的偏移就是 `getBoundingClientRect()` 值本身。
- AX 的 `Position`/`Size` 用全局逻辑点。

规则：

- 槽几何的**唯一事实来源是前端**：前端用 `ResizeObserver` 观察 `.dock-slot`，变化后调用 `set_dock_slot` 上报 CSS rect；后端缓存最新值。
- 后端在「自己窗口 Moved/Resized」事件时，用缓存 rect + 新 `inner_position`/`scale` 重算全局目标。
- 应用位置前做容差判断：`|dx|,|dy|,|dw|,|dh|` 任一 > 2 点才重新设置，避免抖动。
- 多显示器负坐标、菜单栏/Dock 遮挡必须按上述全局坐标处理，禁止「主屏假定」。

## 5. 后端设计

### 5.1 `DockManager` 与状态机

```rust
pub struct DockManager {
    tx: mpsc::Sender<DockCmd>,
    session: Mutex<Option<DockSessionView>>, // 仅面向前端的视图
}

enum DockCmd {
    Start { provider_id: String, cwd: Option<PathBuf> },
    UpdateSlot(Rect),                 // 前端上报，CSS px
    Redock,                           // 由窗口 Moved/Resized 触发
    Stop { mode: QuitBehavior },
    Shutdown,
}
```

- 专用工作线程持有 `mpsc::Receiver`，循环处理命令；**所有 `osascript` 与 AX 调用都在该线程**，禁止阻塞 Tauri 主线程/异步运行时。
- 每轮 `Redock` 实际执行前检查 `window.is_focused()`：
  - 主窗口聚焦：执行贴合。
  - 主窗口失焦（用户点进了终端）：不抢窗口，改为周期性比对；连续 N 轮（如 12 轮）偏差超阈值则进入 `detached` 状态并 emit。
- 状态枚举（emit 给前端）：

```rust
#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub enum DockState { Launching, Docked, Detached, Exited, Error }
```

状态迁移：

```text
Launching ──窗口就位──▶ Docked ──偏差超限/应用失焦──▶ Detached ──Redock──▶ Docked
    │                       │                                   │
    └──失败/应用退出──▶ Error/Exited ◀──终端进程退出────────────┘
```

关闭策略（P1 只实现 Close）：

- `Close`：只关闭我们停靠的那一个窗口（对持有的 AX 窗口执行 `kAXCloseAction`），**绝不 kill iTerm2 进程**。
- `Quit`：P2 可选，仅当该终端是本次会话由我们启动的独立实例时才允许退出应用；否则同 `Close`。
- `Leave`：脱锚不管。

### 5.2 AX 封装（`docking.rs`）

封装以下能力，内部用 `axuielement`：

1. `is_trusted() -> bool`：`AXIsProcessTrusted`。
2. `request_trust() -> bool`：`AXIsProcessTrustedWithOptions` 带 `kAXTrustedCheckOptionPrompt`；**只能由前端按钮点击触发的 command 调用**，不得在启动时自动弹窗。
3. `windows_of(pid) -> Vec<AxWindowHandle>`：应用元素 → `kAXWindowsAttribute`。
4. `main_window_of(pid)`：优先 `kAXMainWindowAttribute`，其次列表第一个。
5. `frame_of / set_frame / raise / close`：`Position`/`Size` 读写、`kAXRaiseAction`、`kAXCloseAction`。

`AxWindowHandle` 内部持有 AXUIElement，仅存于 Rust，不序列化。

### 5.3 `TerminalProvider` trait（`terminal_provider/mod.rs`）

```rust
pub trait TerminalProvider: Send + Sync {
    fn id(&self) -> &str;
    fn is_installed(&self) -> bool;
    /// 启动会话并返回可停靠的窗口句柄；AX 定位由调用方统一执行
    fn launch(&self, ctx: &LaunchContext) -> Result<ProviderWindow, ProviderError>;
    fn close_window(&self, win: &ProviderWindow) -> Result<(), ProviderError>;
}

pub struct LaunchContext { pub cwd: PathBuf, pub project_name: String }

pub struct ProviderWindow {
    pub pid: u32,
    pub ax: AxWindowHandle,   // 可能为空句柄表示待探测
    pub title: String,
}
```

- 注册表：`HashMap<String, Box<dyn TerminalProvider>>`；P1 只注册 iTerm2，但 trait 与注册表一次到位。
- `list_terminal_providers()` 返回 `Vec<ProviderInfo>`（id/name/kind/enabled/installed）。
- `launch` 失败必须有可读错误（区分：未安装 / 未授权 / 启动超时 / 窗口找不到），前端据此渲染对应占位。

### 5.4 iTerm2 provider（P1 主目标）

启动序列：

1. 探测应用路径：设置里的 `app_path` 存在即用；否则依次查 `/Applications/iTerm.app`、`/Applications/iTerm2.app`，最后 `mdfind "kMDItemCFBundleIdentifier == 'com.googlecode.iterm2'"`。
2. `cwd` 为 `None` 时用当前打开的项目根（`AppState.project_root`）；仍未打开项目则用用户主目录。
3. 通过 `osascript` 的 **stdin** 传脚本（避免 shell 引号地狱）：

```applescript
tell application "iTerm2"
    set w to create window with default profile
    tell current session of w to write text "cd " & quoted form of "<cwd>" & " && clear"
    activate
end tell
```

4. 取 PID：`osascript -e 'tell application "System Events" to unix id of first process whose name is "iTerm2"'`（超时 5s；失败则尝试 `pgrep -f "iTerm.app/Contents/MacOS/iTerm2"` 取最大 PID）。
5. AX 找到该 PID 的 `kAXMainWindowAttribute` 窗口，保留句柄并 set_frame 到目标 rect、raise。
6. 若 3 秒内窗口未出现，重试一次，仍失败返回「窗口找不到」错误。

说明与边界：

- 首次执行 `osascript` 会触发系统「墨斗想控制 iTerm2」自动化授权弹窗，`osascript` 可能返回错误码 -1743。检测到 -1743 时返回可读错误，前端提示用户先完成授权。
- 不改用户 iTerm2 的 Profile；「无标题栏」样式是用户侧 Profile 配置，代码不依赖它。
- `close_window` 只对保留的 AX 窗口执行 close 动作，绝不用 `quit`。

### 5.5 CLI provider（P2）

- WezTerm：`wezterm start --cwd <dir>`；注意它可能接入已运行的 GUI 实例，spawn 得到的 PID 可能不拥有新窗口 → 窗口探测回退到「按 app_name 查找进程 → AX 主窗口」。
- Alacritty：用 `alacritty --working-directory <dir>` 新实例；已知 `alacritty msg create-window` **不接受**配置参数，不得用该命令带 cwd。
- kitty：`kitty --single-instance --directory <dir>`；普通启动无需 `allow_remote_control`，只有 `kitty @` 子命令才需要，P2 不用 `@`。
- 自定义命令：`command` 数组逐项替换 `{cwd}` 占位符后 `Command::new` 执行；`app_name` 用于 AX 探测。

### 5.6 Apple Terminal provider（P2）

```applescript
tell application "Terminal"
    do script "cd " & quoted form of "<cwd>" & " && clear"
    activate
end tell
```

### 5.7 IPC 契约

| command | 前端参数（camelCase） | 返回 | 说明 |
|---|---|---|---|
| `list_terminal_providers` | - | `ProviderInfo[]` | 含 installed/enabled |
| `check_accessibility_permission` | - | `bool` | 只读检测 |
| `request_accessibility_permission` | - | `bool` | 弹一次系统授权；仅按钮触发 |
| `get_terminal_settings` | - | `TerminalSettings` | 含默认值合并 |
| `save_terminal_settings` | `settings` | `()` | 写 TOML |
| `start_terminal` | `providerId`, `cwd?` | `DockSessionView` | 启动+首轮贴合 |
| `set_dock_slot` | `rect {x,y,width,height}` | `()` | 前端上报 CSS rect |
| `redock_terminal` | `sessionId?` | `()` | 手动吸回 |
| `stop_terminal` | `sessionId?`, `mode` | `()` | mode: close/quit/leave |
| `get_dock_session` | - | `DockSessionView?` | 恢复 UI 状态用 |

事件（后端 emit）：

| 事件 | payload（camelCase） |
|---|---|
| `dock://state` | `{ sessionId, providerId, state, message }` |

`DockSessionView`：`{ id, providerId, providerName, title, state, message }`。前端不要依赖 AX 细节。

`lib.rs` 窗口事件钩子：

```rust
.on_window_event(|window, event| {
    if matches!(event, tauri::WindowEvent::Moved(_) | tauri::WindowEvent::Resized(_)) {
        // 通过 app.state::<DockManager>() 发送 Redock
    }
    if matches!(event, tauri::WindowEvent::CloseRequested { .. }) {
        // 发送 Shutdown，按 quit_behavior 处理
    }
})
```

## 6. 前端设计

### 6.1 布局（`index.html` + `style.css`）

- `.editor-area` 由 `flex-direction: column` 改为 `row`。
- 新增 `.editor-column`（含 `#tab-bar`、`#editor-content`），`flex: 1; min-width: 0;`。
- 新增 `.terminal-dock`：
  - `width: var(--dock-width, 38%)`；`border-left: 1px solid var(--border)`；`display: flex; flex-direction: column;`
  - `.dock-header`：标题（provider 名 + 项目名）、动作按钮（启动/停止、重新停靠、折叠）、P2 起加 provider 下拉。
  - `.dock-slot`：`flex: 1; position: relative;`，内部叠放状态占位层。
  - `.dock-resize-handle`：`width: 4px; cursor: ew-resize;`，拖动时更新 `--dock-width`，下限 240px、上限 60%。
- 原 `#panel` / `#panel-resize-handle` 标记为 legacy：保留 DOM 与样式，但默认 `display:none`，且新增 `.terminal-dock` 与它们互不影响。

状态占位层内容（`dock://state` 驱动）：

| state | 展示 |
|---|---|
| 未配置/未安装 | provider 名 + 安装提示 |
| 未授权 | 「需要辅助功能权限」+ 授权按钮 → `request_accessibility_permission` |
| Launching | 加载指示 |
| Docked | 无占位（槽透明，终端窗口在后面） |
| Detached | 「终端窗口已脱离」+ 重新吸回按钮 |
| Exited | 「终端已退出」+ 重启按钮 |
| Error | 错误文案 + 重试 |

### 6.2 `DockController`（`app.js` 新增，沿用旧式风格）

```javascript
var dock = {
    providers: [],
    settings: null,
    session: null,
    slotRect: null,
    init: function() {},            // DOMContentLoaded 时调用
    refreshProviders: function() {}, // invoke('list_terminal_providers')
    loadSettings: function() {},
    start: function(providerId) {},
    stop: function(mode) {},
    redock: function() {},
    reportSlot: function() {},       // ResizeObserver 回调，100ms debounce 后 invoke('set_dock_slot')
    render: function() {},           // 按 session.state 切换占位
};
```

要点：

- `init()` 内 `listen('dock://state', ...)` 订阅一次（注意 Tauri 2 `listen` 返回 unlisten 函数）。
- `ResizeObserver` 观察 `.dock-slot`；宽度手柄拖动时同样会触发 `reportSlot`。
- `reportSlot` 上报的是 CSS px，**不要**在前端做 scale 换算。
- 折叠逻辑：折叠 = 隐藏 `.terminal-dock` 并把宽度归零 → 后端收到 rect 宽度为 0 时把终端窗口移出可视区或执行 stop（P1 采用：槽宽为 0 则 stop(mode=leave)，并标记 detached）；展开时重新 start 或 redock。
- 所有按钮事件在 `init()` 内绑定；切换 provider（P2）调 `save_terminal_settings` 持久化。
- 不删除 `createTerminal` / `initXterm` 等 legacy 函数，只把调用入口断开。

### 6.3 设置界面（P2）

在 sidebar 的 settings 面板里做最小表单：默认 provider 下拉、宽度比例滑块、`follow_window` / `auto_redock` 开关、退出行为下拉、每个 provider 的启用开关与路径/命令文本框。改动即时 `save_terminal_settings`。不引入任何前端依赖。

## 7. 实施阶段

### 7.1 P1：布局 + iTerm2 最小闭环

顺序执行，每步都可编译：

1. `Cargo.toml` 加依赖；`cargo check` 通过。
2. `settings.rs`：结构体、`default()`、`load/save`、TOML 单测（缺键回退、round-trip）。
3. `docking.rs`：`Rect` 与 `css_to_global` + 单测（含 scale=2、负坐标、零尺寸）；AX 六项封装；权限两函数。
4. `terminal_provider/mod.rs`：trait、注册表、`ProviderWindow`、`ProviderError`；`iterm2.rs` 按 5.4 实现。
5. `DockManager`：状态机、工作线程、命令循环、容差贴合、detached 判定、`dock://state` emit。
6. `commands.rs`：5.7 全部命令与视图结构体（P1 中 `stop_terminal` 只支持 close/leave）。
7. `lib.rs`：`AppState` 增 `dock_manager: Mutex<DockManager>`；注册命令；`on_window_event` 钩子；非 macOS 返回不支持。
8. 前端：6.1 布局与 6.2 `DockController`；断开 legacy 终端入口。
9. `make check`、`make test`、`make dev` 手工验收（见第 8 节）。

P1 完成定义（DoD）：

- 打开项目后点「启动终端」：iTerm2 新窗口出现在右侧槽，cwd 为项目根目录，iTerm2 应用不被重建/退出。
- 拖动主窗口、改变主窗口尺寸、拖动分隔条：iTerm2 窗口 250ms 内跟随，最终偏差 ≤ 4 点，无抖动。
- 折叠/展开停靠槽：行为符合 6.2 定义，状态正确 emit。
- 点「停止」：仅关闭停靠的 iTerm2 窗口，iTerm2 进程与用户其他窗口不受影响。
- 未授权 AX：槽内出现引导占位；点击授权后可用（系统设置跳转提示文案正确）。
- `cargo test` 全绿；`cargo check --target` 非 macOS 目标编译通过（至少 cfg 门控无编译错误）。
- legacy xterm 代码仍在但不可达，无功能回归。

### 7.2 P2：provider 配置化 + 更多终端 + 设置 UI

1. `cli.rs` + WezTerm/Alacritty/kitty/自定义命令四套配置；`apple_terminal.rs`。
2. 安装探测：`app_path` 存在性；CLI 用 `which` 或 PATH 查找；均失败时 `installed=false`。
3. 注册表按 `settings.providers` 中 `enabled=true` 注册。
4. 设置 UI（6.3）+ provider 下拉切换 + 每 provider 单独验收。
5. `stop_terminal` 支持 quit/leave 全语义。

P2 DoD：五个 provider（含自定义命令）各自满足「启动、cwd 正确、贴合、跟随、只关自己的窗口」；设置改动重启后仍生效；未安装的 provider 在列表灰显且不可选。

### 7.3 P3：边界与体验打磨

1. 全屏/Space：检测主窗口全屏（`window.is_fullscreen()` + 事件轮询），全屏时暂停贴合并 emit 提示，退出全屏自动恢复。
2. 多显示器：验证负坐标与跨屏拖动；终端窗口不得跳屏。
3. 脱锚检测：订阅终端窗口 `kAXMovedNotification`（若 `axuielement` 支持 observer），主窗口失焦期间被用户拖走 → detached + 提示；`auto_redock` 为 true 时回到主窗口后自动吸回。
4. 会话恢复：打开项目时按上次记录重启 provider（cwd 恢复）；关闭时按 `quit_behavior` 处理。
5. legacy 决策：彻底删除 xterm/PTY，或保留为「无 provider 可用」的隐藏后备（需用户确认后再执行删除）。
6. 焦点辅助：可选全局快捷键在主窗口与终端窗口间切换焦点；仅当用户要求时实现。

P3 DoD：全屏进出不崩溃、不跳窗；双显示器下停靠稳定；手动拖走终端后 5 秒内出现「已脱锚」提示且点按钮可吸回；重启应用后能恢复上一次终端。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| AX 授权被拒、开发模式二进制路径变化导致授权失效 | 显式 `request_accessibility_permission` 引导；测试用 `tccutil reset`；错误态独立可读 |
| AppleScript 自动化授权弹窗阻断启动（-1743） | 只在该 provider 首次启动时发生；捕获 -1743 并给引导文案；osascript 全程 5s 超时 |
| 多窗口/多实例导致拿错窗口 | 保留 AX 窗口句柄（不靠标题匹配做主要手段）；`AXMainWindow` 优先；失败进入 detached + 手动吸回 |
| 用户拖走终端后我们反复抢窗口造成对抗 | 仅主窗口聚焦时自动贴合；失焦期间只检测不抢；`auto_redock` 可关 |
| 全屏/Space 停靠失效 | P3 显式检测并降级提示，禁止在全屏时强制移动其他应用窗口 |
| 第三方终端能力差异（Alacritty msg 不支持参数等） | 每 provider 独立命令模板，P2 单独验收；文档已标注已知差异 |
| Retina/多显示器坐标错位 | 统一全局逻辑点换算 + 单测覆盖 scale=2 与负坐标 |
| 误杀用户已有终端进程 | 只对持有的 AX 窗口执行 close；P1 完全禁止 kill/quit |
| `axuielement` API 与文档假设不符 | P1 第 3 步先做 30 分钟 API spike，确认六项封装可用后再写业务；必要时 raw FFI 兜底 |

## 10. 陷阱清单（AI 助手必读）

1. `inner_position()` 是**物理像素**，必须除以 `scale_factor()` 再与 CSS rect 相加。
2. AX `Position/Size` 是**全局逻辑点**；不要用本地窗口坐标，不要在主屏假定下取绝对值。
3. 所有 `osascript`/AX 调用必须在 `DockManager` 工作线程，禁止在 async command 主线程做阻塞调用。
4. `osascript` 脚本经 stdin 传入，cwd 用 `quoted form of`，禁止手拼单引号。
5. 首次 `osascript` 会弹自动化授权，可能返回 -1743；不要把它当普通错误吞掉。
6. 只 close 自己创建的窗口；P1 绝对不要 kill iTerm2 进程、不要 `quit application`。
7. 前端上报 CSS rect、后端换算坐标，前端绝不做 scale 换算。
8. Tauri 事件 payload 必须 `rename_all = "camelCase"`，命令参数已由 Tauri 自动 camelCase。
9. 容差判断（≤2 点不重设）防止「贴合循环 → Moved 事件 → 再贴合」的死循环抖动。
10. 主窗口失焦时停止自动贴合，否则会在用户操作 iTerm2 时与之抢窗口。
11. `.dock-slot` 尺寸变化（分隔条拖动、窗口缩放、sidebar 折叠）都要触发 `set_dock_slot`。
12. 槽宽为 0 是合法信号（折叠），禁止除零、禁止把终端窗口尺寸设为 0。
13. 保留 legacy xterm 代码与 `#panel` DOM，断开入口即可；删除是 P3 的决定，且需用户确认。
14. `axuielement` 版本锁定 0.8，升级前重跑第 8 节清单。
15. 不要引入 tokio、不要引入前端构建工具；后台线程用 `std::thread + mpsc`。

## 11. 边界（明确不做）

- 不开发任何终端仿真、PTY、VT 解析（legacy 代码维持现状）。
- 不做屏幕录制抓流式的「视觉嵌入」（已评估：延迟/权限成本高，与目标相悖）。
- 不做 Windows/Linux 的窗口停靠（本计划只保证 macOS）。
- 不做终端会话在应用内的持久化存储（P3 仅恢复 cwd + provider）。
- 不修改 Monaco 编辑器与文件树的核心能力。
